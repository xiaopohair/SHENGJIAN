## 1. 品牌策略

### 1.1 产品是什么

声键把一支蓝牙语音遥控器变成 Windows 的输入设备。它做三件事：

1. **连接**：扫描、连接、记住设备；处理 BLE / ATVV、断线重连和多遥控器切换。
2. **语音**：按住遥控器语音键说话，文字通过你选择的输入工具落到当前光标。
3. **控制**：把遥控器的 11 个按键映射成动作，按前台应用自动切换方案，用宏把一串动作压成一个键。

它本地运行、不要求账号；语音交给用户选择的输入工具处理，声键本身不上传语音内容，也不建立云端账号（转写历史默认关闭、只存文字）。

### 1.2 用户与场景

- **客厅 / HTPC 用户**：坐在沙发上，用遥控器打开应用、输入搜索词、控制播放。
- **免手 / 无障碍用户**：不方便频繁使用键盘鼠标，需要稳定的语音入口与可预期的按键反馈。
- **效率用户**：按应用自动切换键位，用宏完成重复动作，用语音替代短文本输入。
- **开发者 / 折腾党**：开源、可配置、可诊断；愿意为一次 UAC 换取返回键和音量键的完整捕获。

### 1.3 定位

> 对客厅电脑、免手操作与效率用户，**声键**把小米蓝牙语音遥控器完整接入 Windows——连接、语音、按键、宏、方案、历史，一条链路走完。

定位的重心不是“语音识别”，而是**完整链路**：只做语音，用户还要找输入法；只做按键，用户还要另一套映射工具。声键把两件事放在同一个设备、同一个界面里。

### 1.4 它不是什么

| 不是 | 原因 |
| --- | --- |
| 语音助手 | 不聊天、不做问答、不进对话式界面。它把话变成输入，不把话变成回答。 |
| 输入法 | 不替换用户的输入工具，只负责把语音送进用户已经选好的工具。 |
| 万能遥控器 | 只做 Windows 桌面输入；不做家电控制、不做手机端、不做跨房间中继。 |
| 云端服务 | 没有账号体系；不承诺“云端同步”，也不把“AI”当作卖点。 |

这四条边界同样重要：它们让品牌保持可信，也避免用户带着错误的期待安装。

### 1.5 三个支柱

| 支柱 | 承诺 | 证据 |
| --- | --- | --- |
| **接得上** | 拿起来就能用，连过一次就记住 | BLE / ATVV、设备身份、断线重连、多设备切换、记住上次设备 |
| **打得进** | 声音落在光标所在的地方 | 输入工具可选、Profile 级工具覆盖、实时电平与语音测试、不占用系统默认麦克风 |
| **控得住** | 同一个键，在不同应用里做不同的事 | 前台应用匹配、11 键 × 单击 / 双击 / 长按、按住连发、宏、常用语入口（按平台能力显示） |

### 1.6 品牌人格

- **冷静的工程师**：参数、状态、错误都说清楚；不夸张、不遮掩限制。
- **可靠的桌面工具**：不打断、不抢焦点、不弹无关窗口；失败时给出下一步。
- **克制的幽默**：允许一句“桌面多了一副嗓子”，但不卖萌、不玩梗过度。
- **边界感**：不承诺“全能”，不堆“赋能 / 无缝 / 极致 / 万物”这类词。

### 1.7 品牌承诺

> **按下去，就有反应。**

- 功能层：连接有状态、说话有电平、按键有回显、失败有原因。
- 情感层：不用起身、不用找键、不用等。
- 这句承诺也是验收标准：任何一次交互如果“按下去没反应”，就是品牌层面的缺陷，而不只是 bug。

### 1.8 品牌故事

遥控器本来只能换台。声键让它学会打字、开应用、跑宏。它不跟你聊天，只把你按下和说出的话，翻译成桌面听得懂的动作。

## 2. 命名

### 2.1 为什么叫“声键”

- **声** = 声音 / 语音输入。
- **键** = 按键 / 键盘 / 快捷键。
- 合起来：**一个用声音按下的键**。

选择它的四个理由：

1. **一秒能懂**：不需要先解释“我们是一个语音遥控中间层”。
2. **覆盖两条输入路径**：语音与按键，正好对应产品的两条主链路。
3. **不绑定型号与平台**：不叫“小米遥控助手”，未来接 RC001 / ARN9 或别的平台都不用改名。
4. **可视觉化**：键帽 + 声波，能做成 16px 仍然可辨的标志。

### 2.2 读音与写法

| 场景 | 写法 |
| --- | --- |
| 中文标志 / 标题 | 声键 |
| 英文标志 / 标题 | SHENGJIAN（全大写） |
| 英文正文 | Shengjian |
| 首次出现 | 声键（SHENGJIAN） |
| 拼音 | shēng jiàn |

规则：

- 中文固定写“声键”，不写“声鍵”，不拆成“声 键”。
- 标志中的字距是固定的，不要手动加空格或换字体。
- 不要叫“声键助手”“声键 Pro”“声键智能版”，除非真的存在对应的产品线。
- 品类描述（“小米蓝牙语音遥控器 for Windows”）不是品牌名，不进入标志。

### 2.3 英文命名的取舍

没有采用 VoiceKey / KeyVox / KeyVoice 这类“voice + key”英文名。原因不是不好懂，而是**这个品类已经有同名产品**（语音键盘、语音听写工具），检索、商店命名与商标风险都高。

所以英文采用：

- **品牌名**：SHENGJIAN（拼音，作为标志与标题）
- **描述语**：Voice remote for Windows（只作描述，不进入标志）

这也是很多中文开源工具的常见做法：中文名承担识别，英文用拼音或独立词；描述语负责让英文用户一秒知道品类。

### 2.4 命名检验

| 检验 | 结果 |
| --- | --- |
| 好读 | 两拍，无生僻字 |
| 好记 | 两个字都是高频字，组合有新意 |
| 好听 | 声调一高一降，收尾干净 |
| 可扩展 | 不绑定设备型号、不绑定“语音”单一功能 |
| 不撞车 | 公开检索到同名电子公司；软件类未见直接竞品。商用前仍需商标检索 |
| 可视觉化 | 键帽 + 三段声波，16px 仍可辨 |

### 2.5 备选与取舍

| 备选 | 它好在哪里 | 为什么没有采用 |
| --- | --- | --- |
| 声令 | “一声令下”有气势，掌控感强 | 军事味偏重，像命令工具；与“司令”谐音会让语气变硬 |
| 遥声 | 兼顾“遥控”与“声音”，气质轻 | 语音指向弱，容易被理解成音频或播放类产品 |
| 应声 | “一呼即应”，响应感好 | “应声虫”的负面联想；与语音助手、回声类产品混淆 |
| SayAll | 原型旧名，直白好读 | 泛化、没有中文根，商标与检索都不利 |

### 2.6 商标与检索

- 建议注册类别：**第 9 类**（计算机软件）、**第 42 类**（软件设计与开发）。
- 同时检索“声键”“SHENGJIAN”，以及同音“生煎”以排除冲突。
- 公开工商信息中存在同名电子公司；商用发布前请做专业商标检索。
- 开源发布（GPL-3.0）不构成商标授权；名称与标志的权利由项目作者保留。

## 3. Slogan

### 3.1 主标语

> **声音，就是快捷键。**

为什么是这一句：

- 它把“说”和“按”放进同一句，正好对应产品的两条输入路径。
- “快捷键”是桌面用户的高频词，暗示的是**效率**，不是“AI 助手”。
- 七个字，陈述句，不喊口号；放在安装包、关于页、README 和海报上都不需要改。
- 它同时解释了名字：声键 = 声音做的键。

### 3.2 英文标语

> **Your voice is the shortcut.**

- 句首大写，其余小写；全大写只用于标志或标签（`YOUR VOICE IS THE SHORTCUT.`）。
- 不使用 “Voice is the new keyboard”：这句话已经被用滥，而且暗示“替代键盘”，与产品定位不符。

### 3.3 场景版

| 场景 | 文案 |
| --- | --- |
| 连接页 | 连上它，桌面就多了一副嗓子。 |
| 语音页 | 按住说话，松开出字。 |
| 按键页 | 每个键，都能安排一个动作。 |
| 宏页 | 一句话，跑完一串动作。 |
| 关于页 | 声音，就是快捷键。 |
| 安装包 | 把遥控器，接进 Windows。 |
| README | 小米蓝牙语音遥控器 → Windows 的语音输入、按键映射与宏。 |

### 3.4 备选与使用边界

这些句子可以用，但**不要取代主标语**：

- **一声令下，桌面听令。** —— 适合发布海报、视频高潮；有戏剧性，不适合日常界面。
- **把遥控器，接进 Windows。** —— 描述性副标，适合 README、技术介绍。
- **按一下，说一句。** —— 交互演示、短视频；太短，撑不起品牌。
- **桌面多了一副嗓子。** —— 品牌故事、社交媒体；不适合正式物料。

### 3.5 不要用

- 赋能 / 无缝 / 极致 / 全场景 / 万物 / 下一代 / 重新定义
- “你的全能语音助手”
- “让 AI 改变你的工作方式”
- “一句话掌控万物”

这些词会让产品听起来像一个万能 AI，而它实际是一个**具体、有限、可靠**的桌面工具。品牌的信任来自边界清晰。

## 4. 标志

### 4.1 构成

标志由三个几何元素组成，比例固定：

| 元素 | 规格（viewBox 12 14 40 33） |
| --- | --- |
| 键帽顶面 | 40 × 30，上窄下宽；顶边 28，底边 40，圆角约 6.5 |
| 声波 | 3 段，宽 7，高 11 / 20 / 14，圆角 3.5，间距 3.5，**挖空** |
| 键沿 | 底部 3 单位，深青 `#2E8F76` |
| 整体比例 | 40 : 33（1.21:1） |

颜色：

- 深底版顶面渐变：`#8BE0C7` → `#5AC8AA`（55%）→ `#3FA98C`
- 浅底版顶面渐变：`#1E9A7E` → `#0F7A63`（55%）→ `#0A5A49`
- 键沿：深底版 `#2E8F76`，浅底版 `#08493B`
- 声波：透明挖空（不是黑色填充），因此可以放在任意底色上

浅底版不是把深底版整体调暗，而是单独的调色：顶部去掉薄荷高光，主体落到与浅色主题强调色一致的 `#0F7A63`，这样既有绿色的识别度，又能在纸白/浅灰上撑住 4.8:1 的对比。对比示意见 [`png/light-surface-contrast.png`](png/light-surface-contrast.png)。

### 4.2 含义

- **键帽**：遥控器上的按键，也是键盘上的键。
- **声波**：声音；三段而不是五段，是为了在 16px 仍然能读出来。
- **键沿**：按下去的落点。它让标志有厚度，而不是一张贴纸。

没有画麦克风：麦克风是语音助手的高频符号，会把产品误解成“聊天工具”。键帽 + 声波更接近产品真实的样子——一个能说话、也能按的输入设备。

### 4.4 安全边距与最小尺寸

- 安全边距 **x = 字标中“键”字高度的 1/3（约 28 单位）**。
- 标志四周至少留出 x；小于这个距离时，改为只用主标记，不要挤字标。
- 主锁定最小宽度 **160px**；主标记最小 **16px**；应用图标最小 **16px**。
- 不要用“加底色块 / 加描边 / 加阴影”的方式解决对比度，改用深底或浅底版本。

### 4.5 使用禁忌

- 不要拉伸、压扁、旋转或倾斜。
- 不要改变色相；不要给标志加发光、描边、投影。
- 不要换字体重新排字标，也不要在标志上叠字。
- 不要把键帽做成大面积背景纹理；它是识别元素，不是图案。
- 深底用 dark 版本，浅底用 light / on-light 版本（键帽已经是松青·深），不要用滤镜“调”出来。
- 单色标记与单色锁定只用于单色印刷、水印、单色底；不要用它替代彩色主标志做品牌主视觉。
- 只有必须单色时才用 `*-mono`；浅底默认用松青·深版本，不要用滤镜把亮松青“压暗”来充数。

### 4.6 应用图标与托盘

- **应用图标**：1024 × 1024，圆角 230 的深色底；标记高度 700（约 68%），带 1px 内描边与轻微松青光晕。深色底让它在深浅桌面上都成立。
- 托盘：跟随任务栏明暗——深色任务栏用亮松青（`tray-16-color.svg` 的 16 / 32 PNG），浅色任务栏用松青·深（`tray-16-deep.svg` 的 16 / 32 PNG）。白色 / 墨色单色版本保留给极端对比或单色场景。
- **任务栏 / 窗口图标**：同样跟随任务栏明暗——深色任务栏用 `mark`（亮松青），浅色任务栏用 `mark-on-light`（松青·深）；带深色底的完整应用图标用于桌面、开始菜单与安装包。
- **侧栏 / 关于页**：跟随应用主题；深色主题用亮松青，浅色主题用松青·深。两枚资产几何一致，切换不应造成布局位移。
- Windows 图标应从 SVG 重新导出各尺寸，不要用 1024 PNG 直接缩到 16px。
- Tauri 项目可在 `apps/shengjian-desktop` 下运行 `pnpm tauri icon ../../brand/logo/shengjian-app-icon.svg` 重建图标集，再按平台覆盖托盘图标。

| **薄荷** Mint | `#8BE0C7` | 高光、成功态、slogan 重音 | 不单独承载信息；浅底不可用于文字 |
| **深潭** Deep | `#2E8F76` | 标志键沿、次级按钮、图形阴影 | 与松青同族 |
| **雪** Snow | `#E9EFF7` | 深底正文、浅色标志 | 不要用纯白大面积替代 |
| **纸** Paper | `#F2F5F4` | 浅色底、浅色任务栏、打印 | 浅底上的正文用墨色 |
| **雾** Mist | `#8B99AC` | 辅助文本、说明、版本号 | 不用于正文长段落 |

### 5.2 比例

- 墨 60%
- 石板 20%
- 松青 12%
- 薄荷 5%
- 雪 3%

强调色只做“可操作 / 正在听 / 已连接”的信号，不做大面积背景。浅色物料反过来：纸为主，墨为字，松青·深只做重点。

### 5.3 对比度

- 松青 on 墨：**9.4:1**（可用于正文级强调）
- 雪 on 墨：**约 16:1**（正文）
- 墨 on 松青：**9.4:1**（按钮文字）
- 松青·深 on 纸：**4.8:1**（浅底标志 / 重点文字 / 浅色主题按钮）
- 松青 on 纸：**约 1.9:1**；只适合深色背景，浅底请换松青·深
- 薄荷 on 纸：不足 2:1，不可用于文字

### 5.4 用色规则

- 危险红 `#EF6B73` 只用于破坏性操作与错误，不进入品牌物料。
- 浅色背景的品牌绿只用松青·深 `#0F7A63`；亮松青只用于深色背景或大面积图形。
- 浅色底不使用薄荷色文字；深色底不要让纯白 `#FFFFFF` 大面积出现。
- 同屏强调色不超过两种（松青 + 薄荷算一组）。
- 状态色不要拿来“装饰”；每个颜色都要能对应一个状态或动作。

## 6. 字体

### 6.1 字标

- **Maple Mono NF CN Bold**（SIL OFL 1.1），已转曲，字距 0.12em，归一化到 1000 单位高。
- 圆角端子、等宽骨架、轻微机械感；与键帽的圆角几何同族。
- 只用于“声键 / SHENGJIAN”。不要拿它排正文、按钮或大段标题。
- 字标轮廓来自开源字体，资产中不附带字体文件；如替换字标，请保留 OFL 声明。

### 6.2 界面字体

| 用途 | 字体 | 说明 |
| --- | --- | --- |
| 中文界面 | **MiSans**（推荐）/ Microsoft YaHei UI（当前实现） | MiSans 免费商用，与小米生态一致；当前构建使用系统雅黑 |
| 西文界面 | **Segoe UI Variable**（Windows 11）/ **Inter**（跨平台） | 沿用系统字体，降低打包体积 |
| 等宽 / 技术值 | **Cascadia Mono** / Fira Code / Maple Mono | 版本号、电量、快捷键、日志 |

### 6.3 字号阶梯

| 用途 | 字号 | 行高 |
| --- | --- | --- |
| 页面标题 | 26–32 | 1.2 |
| 区块标题 | 20 | 1.35 |
| 卡片标题 | 16 | 1.45 |
| 正文 | 14 | 1.6 |
| 辅助 | 12–13 | 1.7 |
| 标签 / 版本 | 10–11（mono + 字距） | 1.4 |

### 6.4 排版规则

- 中文与西文之间加空格；数字、版本、快捷键用等宽字体。
- 快捷键统一写 `Ctrl + N`、`Win + Shift + S`，不写 `control n`。
- 中文正文不小于 12px；不要给中文正文加 700 以上字重。
- 中英文混排用中文标点；英文标语末尾保留句号。

## 7. 图形语言

### 7.1 波形

- 只用 3–8 段，圆角端子，段高不等；对应语音、实时电平、转写进度。
- 界面里的实时电平使用薄荷 → 松青渐变。
- 不画密集频谱、不画随机噪点；波形必须对应一个真实状态。

### 7.2 键帽

- 键帽只作为标志 / 图标元素，不做大面积背景纹理。
- 需要“按键”意象时，用一枚键帽 + 一条动作说明，而不是铺满屏幕的键盘。

### 7.3 圆点

- 6px 状态点：连接中、已连接、异常。
- 已连接可加外发光；圆点只表示状态，不做装饰。
- 不要在同一屏出现超过 3 个状态点。

### 7.4 动效

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 正在听（呼吸） | 1600ms | ease-in-out |
| 按下回弹 | 120ms | ease-out |
| 连接 / 状态切换 | 240ms | ease-out |

遵守 `prefers-reduced-motion`；动效只做状态反馈，不做入场表演。

### 7.5 图标

- 界面图标沿用 **Lucide** 线性图标，1.5px 描边、圆角端点。
- 不混用填充图标与线性图标；不使用彩色图标。
- 图标-only 按钮必须有 `aria-label`（现有 `IconButton` 已处理）。

## 8. 应用

### 8.1 任务栏与开始菜单

- 任务栏：透明底主标记；深色任务栏用亮松青，浅色任务栏用松青·深。
- 开始菜单 / 桌面 / 安装包：深色圆角底的应用图标。
- 图标尺寸：16 / 24 / 32 / 48 / 64 / 128 / 256 / 512 / 1024 + `app-icon.ico`。

### 8.2 侧栏与标题栏

- 侧栏顶部：主标记 24–28px + “声键” + 版本号；不放大标志。
- 标题栏保持无边框自定义，只放窗口控制；品牌在侧栏，不在标题栏重复。
- 关于页：字标 + 版本 + 平台 + 许可 + slogan；可作为品牌的主展示位。

### 8.3 安装包

- 安装包标题、快捷方式、关于页使用同一套字标与图标；不要给安装包单独设计一枚图标。
- 首次配置只需三步：连接遥控器 → 选择语音工具 → 设置语音热键。
- helper 首次安装需要一次 UAC；安装包文案要提前说明，避免“为什么突然要管理员权限”。

### 8.4 GitHub 与文档

- 社交预览：`social/github-social-preview.png`（1280 × 640）。
- README 顶部：横排主锁定 + 一句 slogan + 三个功能标签。
- Release 说明：版本号用等宽字体；不要用彩色 emoji 代替状态。

### 8.5 宣传物

- 深底 + 细网格 + 松青波形；不要用库存照片、3D 渲染、夸张光效。
- 一张物料只用一个重点：要么标志，要么 slogan，要么产品截图。
- 产品截图要真实；不要用假数据伪造“AI 能力”。

## 9. 文案

### 9.1 原则

1. **说人话**：短句，动词开头，具体名词。
2. **说具体的事**：写“按住说话，松开出字”，不写“无缝语音交互”。
3. **承认限制**：仅 Windows、未签名、需要一次 UAC、RC001/ARN9 尚未支持。
4. **出错先给原因，再给下一步**：不要只说“失败”，要给可执行的恢复路径。
5. **不制造焦虑**：不用“再不升级就落后”这类话。

### 9.2 状态文案

| 场景 | 文案 |
| --- | --- |
| 未连接 | 还没有连接遥控器。按一下遥控器上的任意键，或点击“扫描”。 |
| 扫描中 | 正在找附近的遥控器…… |
| 已连接 | 已连接。按住语音键说话，松开出字。 |
| 低电量 | 电量 18%。建议先充电，避免语音链路中途断开。 |
| 语音中 | 正在听……说完松开语音键。 |
| 转写完成 | 已写入当前光标。 |
| 权限失败 | 增强捕获需要管理员权限。点击“安装/更新 helper”，在 UAC 弹窗里选择“是”。 |
| 设备不支持 | 这支遥控器还没有身份映射。可以先用通用模式连接，或查看设备支持列表。 |

### 9.3 Do / Don't

| 这样写 | 不要这样写 |
| --- | --- |
| 按住说话，松开出字。 | 赋能全场景智能输入体验。 |
| 每个键，都能安排一个动作。 | 一句话掌控万物。 |
| 连上之后，它会记住你的遥控器。 | 无缝连接，极致流畅。 |
| 遥控器电量低了，充一会儿再继续。 | AI 驱动的下一代桌面交互。 |
| 这个键在当前应用里还没有安排动作。 | 你的全能语音助手。 |

### 10.2 重建

```powershell
# 1. 字标轮廓（需要 Maple Mono NF CN Bold 已安装）
powershell -NoProfile -ExecutionPolicy Bypass -File brand/tools/build_wordmark.ps1

# 2. 生成 SVG 与渲染清单
python brand/tools/build_assets.py

# 3. 渲染 PNG（需要系统 Edge；会启动无头浏览器）
powershell -NoProfile -ExecutionPolicy Bypass -File brand/tools/render_png.ps1
```

修改标志几何时，编辑 `brand/tools/build_assets.py` 中的 `FACE` / `BASE` / `UNION` / `BARS`，再重新生成；不要直接手改 `brand/logo/*.svg`，否则下次构建会覆盖。
