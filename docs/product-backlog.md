## 待办：推荐按键方案按型号拆分（2026-11-19）

**背景**：`config/button-profiles.json` 是由 `config/recommended-button-profiles/*.json` 聚合生成的，
CI 用 `--check` 强制两者一致。这个"目录 → 聚合"的模型在新增方案时**每次都会踩**：

- 只改聚合文件、忘了加源文件 → CI 的目录一致性校验失败（0.9.4 就是这个原因红的）；
- 反过来只加源文件、忘了跑 `pnpm config:build` → 聚合没更新，界面看不到新方案；
- `bundleVersion` 写在 `catalog.json` 里，改了聚合文件里的版本号会被下一次 build 覆盖；
- 聚合按目录排序生成，新增方案会改变 `profiles[i]` 下标，任何按下标写的断言都会碎（0.9.5 又踩了一次）；
- 方案的键集白名单（JS 校验 / Rust `is_profile_button`）两处维护，静音键那次两边不一致，
  只能把绑定从模板里拿掉。

**下个版本计划**：拆成"按型号一份"的文件，去掉聚合这一层。

- `config/recommended-button-profiles/<MODEL>.json`（如 `CHROMECAST.json`、`RC003.json`、`generic.json`），
  一份文件里放该型号的推荐方案与版本号；
- 运行时按当前型号只读那一份，缺文件就用 `generic`，不再有全局聚合与全量重排；
- 打包改为拷贝整个目录（`resources/config/recommended-button-profiles/*`），
  安装包里不出现聚合文件；
- 校验脚本从"目录 vs 聚合一致"降级为"单文件 schema + 键集白名单"，两处白名单合并成一份
  （由 Rust 生成或由 JSON schema 驱动），彻底消除双份维护。

**验收**：新增一个型号的推荐方案只需新增一个文件；`config:check` 通过；界面与安装包都拿到它；
不再需要 `config:build`。

### 2. 三键 / 任意组合键：虚拟 HID 键盘评估 ✅ 评估完成 + 原型已验证通过（2026-11-17）

详见 [winuhid-evaluation.md](winuhid-evaluation.md)。要点：MIT 许可、UMDF2 + 系统内置 VHF、
HVCI 下可用；设备对象只允许管理员/ SYSTEM / UMDF 创建（正好由提权助手持有）；HID 描述符在运行时
下发，**键盘要自己写**（仓库只带鼠标与手柄）；安装要信任其发布者证书。

**原型结果**：用 MoteDeck 的安装器装好驱动（`ROOT\WINUHID\0000`），PowerShell P/Invoke
`WinUHid.dll` 创建虚拟键盘并发送 `Ctrl+Shift+Alt` / `Ctrl+Alt`；低级键盘钩子显示三键/两键
同帧到达且 `flags=0x0`（非注入），**Chatterfly 语音条被成功拉起**。

**产品化进展**：

1. ✅ **键盘描述符与报文编码已沉到 Rust**（`helper/hid-host/src/virtual_hid.rs` + 桥接 `K` 协议，
   提权助手持有虚拟设备）；2026-11-17 真机端到端通过：`Ctrl+Shift+Alt` → `path=virtual_hid`
   → 钩子三键 `flags=0x0` → Chatterfly 弹条并出字。
2. ✅ **后端降级已接**：`report_layer → virtual_hid → send_input`，互斥、逐级回落、各有判据日志；
   释放统一挂在 `release_voice_hold_hotkey()`。
3. ✅ 驱动分发：随包官方驱动包（官方 CA，不重新签名）+ MIT 声明；`WinUHid.dll` 放在助手同目录；
4. ✅ 安装/卸载与 UI：设置页「虚拟键盘」行显示 `可用/未安装` + 安装/卸载按钮，由提权助手执行
   （无 UAC）；卸载清设备 + 驱动包、保留证书；热键超过两键且驱动未装时在热键行提醒。
