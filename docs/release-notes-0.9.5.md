# 声键 0.9.5 发布说明

日期：2026-11-19

> 本文件在 `v0.9.5` tag 推送时由 release workflow 逐字发布（`body_path`）。

## ⚠️ 紧急修复：请升级

0.9.4 存在**语音全局失效**的严重缺陷——所有机型按下语音键都调不起输入法，
并且可能出现「键盘像被按住」的情况。**建议所有 0.9.4 用户升级到 0.9.5。**

## 修了什么

### 1. 所有机型语音失效（0.9.4 引入）

为 Chromecast 的按键报告新增的分支判断写成了「只要输出长度是 3 就返回」，
把其它 3 字节的 I/O 一并吞掉。后台组件的按键记账因此归零，
报告层合成被判定为不可用，语音热键发不出去 → 输入法不响应；
修饰键因此没有及时释放，表现为键盘像被按住。

现在改成「长度 3 **且** 首字节为 `0x02`」两个条件同时成立才走新分支，否则落回原路径。

### 2. 微信输入法语音条不出现

按下语音键时有三条互斥路径：报告层合成 → 虚拟键盘 → SendInput。
微信接受注入键，却被排到了虚拟键盘路径；而这次虚拟键盘没有把键真正发出，
于是什么都不发生。

现在虚拟键盘只服务「只吃报告层」的输入法（豆包 / Chatterfly），其余走 SendInput。

修复后日志：

```
voice_attempt tool=wechat path=send_input
chord_press   result=ok
voice_verify  verdict=reacted
```

## 未受影响

- Chromecast TV Remote 的设备支持、按键映射、界面（产品图 / 热区 / 配对指南）都保持 0.9.4 的样子；
- 小米三款的默认按键方案（方向 / OK / 返回 / 音量±）不变。

## 自检

升级后如果语音仍不工作，把这两行日志发给开发者即可定位：

- `voice_attempt ... path=`
- `voice_synth_ack ... owned_usages=`

`owned_usages` 正常应为 3；为 0 说明后台组件没有接管按键。
